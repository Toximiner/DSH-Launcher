# DeepSeek Harness Launcher

**Русский** | [English](README.en.md)

Небольшое Electron-приложение: окно, которое открывает **DeepSeek Harness**
(`dsh web`) и ведёт его процесс заодно.

## Как работает

- **Клик по ярлыку «DeepSeek Harness»**:
  - если порт `3080` не слушается — лаунчер сам запускает
    `dsh --profile web --no-open`, подхватывает строку
    `dsh web: http://127.0.0.1:3080/?token=…` из stdout dsh и открывает
    её в окне (сервер выдаёт сессионный куки, он запоминается в профиле
    приложения и обычно больше не нужен);
  - если dsh **уже запущен** (например, из терминала) — окно подключается
    к нему. Куки, если он ещё валиден, подхватывается автоматически;
    иначе окно попросит вставить URL с токеном из того терминала, где
    работает dsh.
- **Плагин маркета.** Перед тем как запустить dsh, лаунчер проверяет, что в
  профиле (`$DSH_HOME/profiles/<профиль>/package.json`, по умолчанию
  `~/.dsh`) стоит плагин `dshmarket`. Если нет — окно спрашивает:
  «Установить» (выполняет `dsh plugin --profile web add dshmarket` с живым
  логом), «Не сейчас» или «Не спрашивать больше». Отказ навсегда хранится в
  `~/.config/dsh-launcher/market-prompt.json` — удалите файл, чтобы вопрос
  вернулся. К уже запущенному dsh вопрос не задаётся.
- **История введённого.** Обычные `↑`/`↓` в поле ввода dsh поднимают ранее
  отправленные сообщения (как в терминале; до 50, повторы подряд не
  дублируются), `Esc` возвращает недописанный черновик, `↓` ниже самого
  свежего — пустое поле. Стрелки перехватываются, только когда курсор стоит
  в начале поля; `Shift+↑/↓` (выделение) и сочетания с `Ctrl`/`Alt` (их
  использует сам dsh) не затрагиваются. Тексты лежат в
  `~/.config/dsh-launcher/input-history.json`, в журнал лаунчера не пишутся;
  выключается в «Настройках» → «Общие». Функция опирается на редактор поля
  dsh: после крупного обновления dsh она может перестать срабатывать.
- **Закрытие окна** → весь процесс dsh останавливается (SIGTERM,
  через 4 с — SIGKILL): и тот, что запустил лаунчер, и «усыновлённый»
  после самовозрождения dsh (его процесс ищется по слушающему порту).
  Чужой (запущенный вручную в терминале до открытия лаунчера) dsh не
  трогается. Если сам лаунчер получает SIGTERM/SIGINT/SIGHUP (pkill,
  завершение сессии) — он закрывается штатно и останавливает dsh так же
  (повторный сигнал или зависание дольше 8 с — сразу SIGKILL); прямой
  `kill -9` лаунчеру перехватить нельзя, и в этом случае dsh переживёт его.
- **Проверка обновлений.** При старте лаунчер спрашивает GitHub о последнем
  релизе себя (`Toximiner/DSH-Launcher`) и npm о последней версии
  `@deepseek-ai/dsh`. Если есть новая версия и dsh запускается самим лаунчером,
  перед стартом dsh окно спрашивает: «Обновить / Не сейчас / Не спрашивать
  больше» (запоминается на версию — новый релиз спросит снова). В вопросе
  об обновлении лаунчера — «Что нового»: изменения всех версий новее
  установленной; после обновления при первом запуске новой версии окно с
  изменениями показывается ещё раз. Список релизов запоминается с меткой
  ETag: при старте GitHub спрашивается «изменилось ли» — ответ 304 не
  расходует лимит запросов, а новый релиз виден сразу; GitHub недоступен —
  берётся список из кэша, если ему меньше часа.
  - Обновление лаунчера: скачивание .deb из релиза (прогресс на странице,
    sha256 сверяется с digest ассета в GitHub) и установка через pkexec —
    polkit просит пароль системным диалогом; под root пакет копируется в
    каталог root и ещё раз сверяется по sha256, затем `apt-get install`;
    после успеха — авто-перезапуск лаунчера. Нет pkexec / отмена
    пароля / ошибка — страница с командой для терминала и кнопкой
    «Проверить ещё раз».
  - Обновление dsh: `npm install -g @deepseek-ai/dsh@<версия>`, если глобальный
    prefix npm доступен без sudo; если prefix системный (npm и prefix не в
    домашнем каталоге) — та же установка через pkexec, polkit просит пароль
    системным диалогом, как при обновлении лаунчера; для nvm и `~/.npm-global`
    (root оставил бы там файлы, которые пользователь потом не обновит) —
    команда для терминала. После успеха dsh стартует сразу с новой версией.
  - В режиме подключения к уже работающему dsh вопросы не показываются.
  - Запросы уходят сразу при старте, параллельно остальному; перед
    запуском dsh лаунчер ждёт их ответа не дольше ~8 с (без сети запрос
    падает сразу, и лаунчер просто не спрашивает). Отключение:
    `DSH_LAUNCHER_NO_UPDATE_CHECK=1`. Запросы идут через системный прокси
    (настройки GNOME/KDE или `HTTPS_PROXY`), если он задан.
  - Пока лаунчер работает, проверка повторяется раз в 12 часов. Новая
    версия посреди работы ничего не прерывает: плашка в углу окна (раз
    на версию) и пункт «Справка → Обновить … до X…». Его окно — «Что
    нового» и «Обновить сейчас»: лаунчер перезапускается (dsh
    останавливается) и сразу ставит обновление, без повторного вопроса.
    Те же кнопки — в «Справка → Проверить обновления…». Выключается
    отдельной галочкой в «Настройках».

- **Меню окна** (видно постоянно; подписи — на языке окна, RU|EN):
  - «Файл» — «Настройки…» (Ctrl+,; см. ниже), «Перезапустить dsh…»
    (например, после обновления плагинов; с подтверждением; dsh, запущенный
    не лаунчером, не трогается) и «Выйти» — штатное завершение (останавливает
    dsh, который запустил лаунчер).
  - «Правка» — «Вырезать», «Копировать», «Вставить», «Выделить всё» (то же,
    что в контекстном меню; Ctrl+X / C / V / A работают и без меню).
  - «Вид» — перезагрузка (F5, Ctrl+Shift+R — без кэша), масштаб (Ctrl+= /
    Ctrl+− / Ctrl+0, запоминается), поиск по странице, проверка орфографии
    (вкл/выкл), полноэкранный режим (F11).
  - «Справка»:
    - «Проверить обновления…» — последний релиз на GitHub и последняя версия
      `@deepseek-ai/dsh` на npm, по каждому компоненту; если есть новая —
      «Что нового» и кнопка «Обновить»;
    - «Вернуть предыдущую версию…» — если новая версия не понравилась: список
      прошлых релизов (до пяти) и кнопка «Вернуть»; лаунчер перезапускается и
      ставит выбранную версию тем же путём, что обновление, и больше не
      предлагает более новую (вернуть — «Настройки → Обновления»);
    - «Журнал dsh…» — последние строки `dsh.log`, токены и ключи скрыты;
    - «Открыть папку логов», «Сохранить отчёт…» (см. «Логи и диагностика»);
    - «О программе» — версии лаунчера и бэкенда dsh, путь к dsh, Node.js, ОС,
      GPU-ускорение, путь к логам; одной кнопкой весь блок копируется в
      буфер обмена для отчёта о проблеме.

  «О программе», «Проверить обновления», «Журнал dsh», «Настройки» и другие
  диалоги открываются внутри окна лаунчера — карточкой поверх затемнённого
  GUI dsh (он не перезагружается). Закрыть — «Закрыть» или Esc.

- **Окно «Настройки»** («Файл → Настройки…», Ctrl+,) — разделы в меню слева:
  - общие — язык интерфейса (Авто / Русский / English), проверка орфографии;
  - обновления — проверять ли при запуске и раз в 12 часов (две галочки),
    «снова спрашивать» об отложенных версиях;
  - запуск dsh — программа dsh (автоматически или выбранный файл), профиль,
    рабочая папка, порт (лаунчер передаёт его dsh: `--port`);
  - окно — «Крестик прячет окно в трей» (dsh работает дальше; меню значка:
    «Открыть», «Перезапустить dsh», «Выйти»; нужен трей на рабочем столе —
    в GNOME расширение AppIndicator, в Ubuntu оно есть; спрятанное окно
    вернёт и повторный запуск лаунчера), «Сообщать, когда агент закончил
    ответ или ждёт вас» — подтверждение команды, вопрос, согласование плана
    (окно не в фокусе — системное уведомление с названием сессии,
    точка на значке трея, под X11 мигает кнопка на панели задач; «…и
    звуком» — отдельной галочкой; видно только сессию, открытую в окне);
  - графика — GPU-ускорение (Авто / Выключено, с текущим состоянием), окно
    на Wayland (Авто / Wayland / X11 — если окна не видно), песочница
    Chromium (по умолчанию выключена, см. «Про `--no-sandbox`»).

  Язык, орфография, проверка раз в 12 часов, «снова спрашивать», трей и
  сигнал «агент закончил» действуют сразу; остальное — после перезапуска
  лаунчера (плашка с кнопкой «Перезапустить лаунчер» вверху окна). «Сохранено»
  и ошибки всплывают в углу окна. Хранится в
  `~/.config/dsh-launcher/settings.json`. Переменные окружения (`DSH_BIN`,
  `DSH_ARGS`, `DSH_CWD`, `DSH_PORT`, `DSH_LAUNCHER_LANG`,
  `DSH_LAUNCHER_NO_UPDATE_CHECK`, `DSH_LAUNCHER_NO_GPU`,
  `DSH_LAUNCHER_OZONE`) важнее: такое поле в окне неактивно и подписано.

- **Поиск по странице (Ctrl+F)** — панель в правом верхнем углу со
  счётчиком совпадений; Enter / Shift+Enter (F3 / Shift+F3) — следующее /
  предыдущее, Esc — закрыть.

- **Проверка орфографии** в полях ввода (русский и английский): варианты
  исправления и «Добавить в словарь» — по правому клику на подчёркнутом
  слове. Словари Chromium скачивает при первом включении (без сети проверка
  не работает).

- **Размер окна запоминается** между запусками.

- **Логи и диагностика:** «Справка → Открыть папку логов»; в «О программе»
  — путь к логам и состояние GPU-ускорения. Если GPU отключён после сбоев
  GPU-процесса, там же кнопка «Включить GPU снова».
  - «Справка → Сохранить отчёт…» (и кнопка в «О программе») — архив
    `dsh-launcher-report-<дата>.tar.gz`: версии, система, сессия, GPU,
    настройки, журнал лаунчера и хвост журнала dsh; токены и ключи скрыты.
    Если лаунчер падал — ещё и дампы падений (до трёх за 30 дней): Electron
    сохраняет их только локально, в `~/.config/dsh-launcher/Crashpad`, и
    никуда не отправляет.
    Его прикладывают к сообщению о проблеме на GitHub.
  - Если лаунчер в прошлый раз завершился аварийно (падение, `kill -9`,
    выключение питания), при следующем запуске в углу окна — плашка с
    кнопками «Журнал…» и «Сохранить отчёт…».

- **Контекстное меню по правому клику** — и в GUI dsh, и на служебных
  страницах: в поле ввода «Вырезать», «Копировать», «Вставить», «Выделить
  всё»; на выделенном тексте — «Копировать»; на ссылке — «Копировать адрес
  ссылки». Подписи — на языке окна.
- **Защита от чужих страниц в окне.** GUI dsh показывает текст модели и
  интерфейсы плагинов, поэтому:
  - команды лаунчера (`dshlauncher://…`: настройки, обновление, перезапуск)
    принимаются только со страниц самого лаунчера — в их ссылках случайный
    ключ, свой на каждый запуск; запрос без ключа отклоняется (строка в
    журнале);
  - ссылка на другой сайт открывается в системном браузере, а не в окне;
  - разрешения браузера — только запись в буфер обмена и полноэкранный
    режим; микрофон, камера, геолокация, уведомления — отказ (в журнале —
    какое разрешение и для какой страницы).

## Системные требования

Проверено на **Ubuntu 26.04** (рабочий стол, Wayland) и на чистых
**Ubuntu 26.04**, **Ubuntu 24.04** и **Debian 13** (amd64) в контейнере:
пакет ставится через `apt` со всеми зависимостями, сценарии установки dsh
проходят до открытия интерфейса. Пакет ставится и на системы со старыми
именами библиотек (без суффикса `t64`) — Debian 12, Ubuntu 22.04; их
регулярно не проверяем.

Самому лаунчеру Node.js не нужен — Electron входит в пакет. Но
**DeepSeek Harness** — это npm-пакет, и ему нужны:

- **Node.js 22 или новее** и npm;
- **pnpm** — для установки плагинов (в том числе маркета).

Чего не хватает, окно лаунчера подскажет само. Как получить Node.js:

| Система | Node.js из apt | Что делать |
|---|---|---|
| Ubuntu 26.04 | 22 — подходит | `sudo apt install nodejs npm`, затем `sudo npm install -g @deepseek-ai/dsh pnpm` (системный npm ставит в `/usr/local`, нужен sudo) |
| Ubuntu 24.04 | 18 — **слишком старый**, dsh на нём не запустится | Node.js 22+ через nvm (ниже) или пакеты NodeSource |
| любая | — | **nvm**, без sudo — тогда dsh, pnpm и маркет лаунчер поставит сам кнопкой «Установить» |

Установка nvm и Node.js:

```sh
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.3/install.sh | bash
# откройте новый терминал
nvm install 22
```

## Запуск из терминала

Из каталога проекта:

```sh
npm install          # только первый раз
npx install-electron # Electron 44+ не скачивает бинарник автоматически
npm start
```

## Настройка

Значения по умолчанию — в `src/env.js` и `src/config.js` (и окно «Настройки»), либо переменные окружения:

| Переменная              | По умолчанию             | Что делает                    |
|-------------------------|--------------------------|-------------------------------|
| `DSH_BIN`               | поиск (см. ниже)         | путь к бинарнику dsh          |
| `DSH_ARGS`              | `--profile web --no-open`| аргументы запуска (как в shell: пробелы, `"…"`, `'…'`, `\`) |
| `DSH_CWD`               | домашний каталог         | рабочая директория dsh        |
| `DSH_PORT`              | `3080`                   | порт web-интерфейса           |
| `DSH_START_TIMEOUT_MS`  | `120000`                 | сколько ждать старта, мс      |
| `DSH_LAUNCHER_LANG`     | выбор в окне / локаль    | язык окон лаунчера: `ru` или `en` |
| `DSH_LAUNCHER_NO_UPDATE_CHECK` | —             | `1` — не проверять новые версии (GitHub Releases + npm) |
| `DSH_LAUNCHER_NO_GPU`   | —                        | `1` — без GPU-ускорения (программный рендер) |
| `DSH_LAUNCHER_OZONE`    | авто                     | окно на Wayland: `wayland` или `x11` (XWayland) |

Язык окон лаунчера (запуск, установка dsh, вопрос про маркет, обновления,
ошибки, диалоги) выбирается в «Настройках» или переключателем **RU|EN** в
правом верхнем углу служебных страниц; выбор запоминается в `~/.config/dsh-launcher/ui-lang.json`. Пока выбора не
было — язык по локали системы (`LC_ALL` / `LC_MESSAGES` / `LANG`): `ru*` —
русский, иначе английский. `DSH_LAUNCHER_LANG=ru|en` задаёт язык
принудительно и перекрывает сохранённый выбор.

Если `DSH_BIN` не задан, лаунчер ищет dsh сам: `/usr/bin/dsh`, `PATH`,
`~/.npm-global/bin`, `~/.local/bin`, `/usr/local/bin`, все версии nvm
(`~/.nvm/versions/node/*/bin`) и `$(npm prefix -g)/bin`. Найденный путь
запоминается в `~/.config/dsh-launcher/dsh-bin.json`. dsh запускается с
своим каталогом в начале `PATH` — так установленный через nvm dsh получает
«свой» node и при запуске с ярлыка.

Журнал процесса dsh пишется в `dsh.log`, журнал самого лаунчера (проверка
обновлений, запуск и остановка dsh, ошибки; со временем, токены скрыты) —
в `launcher.log`: в установленной версии — в `~/.local/state/dsh-launcher/`,
при запуске из исходников — в `logs/` проекта. Оба файла после 2 МБ (и при запуске, и во
время работы) сдвигаются в `*.1`, заменяя прежний: на диске не больше
четырёх файлов журналов, ~8 МБ.

## Клавиши в окне

Работают при любой раскладке (RU/EN); те же действия — в меню окна:

| Клавиши             | Действие                    |
|---------------------|-----------------------------|
| `F5` / `Ctrl+R`     | перезагрузить страницу      |
| `Ctrl+Shift+R`      | перезагрузить без кэша      |
| `Ctrl+=` / `Ctrl+-` | шаг масштаба страницы       |
| `Ctrl+0`            | сброс масштаба              |
| `Ctrl+F`            | поиск по странице           |
| `F3` / `Shift+F3`   | следующее / предыдущее совпадение |
| `F11`               | полноэкранный режим         |
| `Ctrl+,`            | «Настройки»                 |
| `Esc`               | закрыть диалог или поиск    |

Масштаб сохраняется между запусками. Нажатия `Alt` (включая смену раскладки
`Shift+Alt`) не уводят фокус в строку меню — его можно спокойно использовать
в сочетаниях GUI dsh.

## Ярлык (если ещё не поставлен)

Готового desktop-файла для dev-ярлыка в репозитории **нет**
(`deb/dsh.desktop` — шаблон для .deb-пакета): файл создаётся локально,
потому что содержит абсолютные пути вашей машины:

```sh
# из каталога проекта:
chmod +x run.sh
cat > dsh.desktop <<EOF
[Desktop Entry]
Type=Application
Version=1.0
Name=DeepSeek Harness
GenericName=AI Chat
Comment=Launcher for DeepSeek Harness (dsh --profile web)
Exec=$PWD/run.sh
Icon=$PWD/icon.png
Terminal=false
Categories=Development;Utility;
Keywords=dsh;deepseek;ai;chat;harness;
StartupWMClass=dsh-launcher
EOF
cp dsh.desktop ~/.local/share/applications/      # пункт в меню приложений
cp dsh.desktop ~/Desktop/ && chmod +x ~/Desktop/dsh.desktop   # иконка на рабочем столе
# GNOME: на иконке на рабочем столе — ПКМ → «Allow Launching»
```

## Пакет для Ubuntu и Debian (.deb)

Готовые пакеты публикуются в **Releases** репозитория на GitHub —
проще всего скачать свежий `.deb` оттуда и установить. Что изменилось в
каждой версии — в [CHANGELOG.md](CHANGELOG.md).

### Сборка самостоятельно

Нужны (только на **машине сборки**): Ubuntu/Debian amd64 с `dpkg-deb`
(пакет `dpkg-dev`), Node.js 22.12+ (требование Electron 44) и доступ в
интернет (скачается бинарник Electron ~290 МБ). Самому пакету на целевой
машине node/npm **не нужны** — Electron входит внутрь (Node.js 22+ нужен
только для dsh, см. «Системные требования»).

```sh
git clone https://github.com/Toximiner/DSH-Launcher.git
cd DSH-Launcher
npm install            # только на машине сборки
npx install-electron   # Electron 44+ не скачивает бинарник автоматически
./build-deb.sh         # ~2 минуты (xz-сжатие) → dsh-launcher_<версия>-<ревизия>_amd64.deb

sudo dpkg -i dsh-launcher_*_amd64.deb
# либо: sudo apt install ./dsh-launcher_*_amd64.deb
```

Версия пакета задаётся **в одном месте** — `Version:` в `deb/control`
(формат `X.Y.Z-R`, например `1.0.0-9`); `build-deb.sh` читает её
автоматически. Для локальной сборки новой ревизии меняйте только этот
файл.

Устанавливается:

- `/opt/dsh-launcher/` — приложение и рантайм Electron;
- `/usr/bin/dsh-launcher` — команда запуска;
- `/usr/share/applications/dsh-launcher.desktop` — пункт меню «DeepSeek Harness»;
- `/usr/share/icons/hicolor/256x256/apps/dsh-launcher.png` — иконка.

`postinst` (выполняется от root при установке) настраивает SUID-хелпер
песочницы Chromium (`chown root:root` + `chmod 4755 chrome-sandbox`). Сама
песочница по умолчанию **выключена** (см. «Про `--no-sandbox`») и
включается галочкой в «Настройки → Графика».

Журналы в установленной версии: `~/.local/state/dsh-launcher/dsh.log` (dsh)
и `launcher.log` (лаунчер) — «Справка → Открыть папку логов».

> **Внимание.** Если раньше вручную ставили ярлык
> (`~/.local/share/applications/dsh-launcher.desktop` и/или иконку на
> рабочем столе) — он перекрывает системный (пользовательские файлы
> имеют приоритет). После установки пакета удалите его:
>
> ```sh
> rm ~/.local/share/applications/dsh-launcher.desktop
> rm ~/Desktop/dsh-launcher.desktop 2>/dev/null
> ```

### Устройство кода

`main.js` — только сборка приложения: одиночный экземпляр, порядок запуска
(`onReady`), маршруты `dshlauncher://`, авто-восстановление окна после
перезапуска dsh, закрытие. Остальное — модули `src/`:

| Модули | Что в них |
|---|---|
| `env.js`, `config.js`, `log.js` | параметры запуска (окружение и `settings.json`), журналы и их ротация |
| `state.js`, `launcher.js`, `i18n.js` | общее состояние (окно, процесс dsh, флаги), реестр функций для вызовов между модулями, язык окон |
| `dsh-install.js`, `dsh-process.js`, `dsh-stop.js`, `launch.js` | поиск dsh, запуск и самовозрождение, остановка дерева процессов, доведение окна до GUI |
| `pages.js`, `install-page.js`, `market.js` | служебные страницы, «dsh не установлен», плагин маркета |
| `updates.js`, `updates-live.js`, `whats-new.js`, `updates-logic.js`, `versions.js`, `notes.js` | обновления при запуске и во время работы, «Что нового», версии, описания релизов |
| `dialogs.js`, `settings-window.js`, `dsh-log.js`, `diagnostics.js` | окна-диалоги, «Настройки», журнал dsh, отчёт и сообщение после сбоя |
| `menus.js`, `view.js`, `file-help.js`, `window-state.js`, `tray.js` | меню, «Вид» и поиск, «Файл/Справка», размер окна, трей |
| `util.js`, `system.js`, `ui.js` | чистые функции: разбор аргументов, ключ маршрутов, процессы и порты, пункты меню, горячие клавиши |
| `guard.js`, `proc-log.js`, `prefs.js` | защита окон (переходы, разрешения), команды с живым логом, файлы настроек |

Чистые функции модулей покрыты юнит-тестами (`test/*.js`). Функции из
модулей с electron тесты берут из текста по блокам-маркерам
`/* ===== имя (тест test/X.js) */` … `/* ===== end имя ===== */`;
`test/markers.js` следит, что у каждого блока есть пара, имя не повторяется и
названный тест существует и проверяет эту функцию. Модули
подключают друг друга обычным `require` и вызывают как `pages.showPage()`;
общее состояние — `state.<поле>`. Модули с состоянием дополняют свой
`module.exports`, а не заменяют его, — поэтому циклы между ними не мешают.
То немногое, что живёт в `main.js`, модули получают через реестр
`launcher.<имя>`.

### Тесты

```sh
npm test            # статическая проверка (ESLint) и юнит-тесты модулей src/ (test/*.js)
npm run coverage    # покрытие юнит-тестами (то же в CI — во вкладке Summary сборки)
npm run lint        # только ESLint: неизвестные имена, неиспользуемые импорты и т. п.
test/docker/run.sh  # сценарии установленного .deb в Docker: Ubuntu 24.04, 26.04, Debian 13
```

Docker-сценарии написаны на **pytest** (`test/docker/`):

- `tests/` — сами тесты по темам (завершение работы, обновления лаунчера и
  dsh, обновления во время работы, «Настройки», окна меню, контекстное меню и
  поиск, трей, журналы, диагностика, размер окна и прокси, Wayland); сценарий
  = тест;
- `helpers/` — объекты окон (`windows.py`: главное окно, диалоги, плашка,
  поиск, вопрос об обновлении), запуск лаунчера, процессы, драйвер CDP;
- `fakes/` — подставные dsh, HTTP-прокси и GitHub (`github.py`: список
  релизов лаунчера с ETag и `.deb` к ним — сценарии обновления и отката не
  зависят от настоящих релизов; `run.sh` собирает эти `.deb` из текущего кода
  версиями 2.0.0-1 и 1.0.0-14);
- `conftest.py` — фикстуры (`start`, `gui`, `prompt`, `drv`, `wayland`) и
  выбор сценария: `pytest --scenario <имя>`, `--list-scenarios`.

`run.sh` собирает `.deb` из текущего кода (версией 1.1.0-1), ставит его в
чистые контейнеры и в каждом запускает один сценарий под Xvfb (сценарии
`wayland_*` — под безголовым weston, только на Ubuntu 26.04); окном
управляет протокол отладки Chromium (CDP). Нужны Docker, собранный Electron
и сеть. Только часть сценариев: `test/docker/run.sh close find`, только одна
система: `OSES=26.04`. Логи и отчёты JUnit — в `test/docker/.work/results/`.
Лаунчер в сценариях пишет покрытие своего кода (`NODE_V8_COVERAGE`
main-процесса Electron); по всем сценариям `run.sh` строит отчёт c8 —
`results/coverage.txt` и HTML в `test/docker/.work/coverage/`, на CI — во
вкладке Summary прогона `docker-tests`. Это покрытие всего `main.js` и `src/`,
а не только чистых функций, как у `npm run coverage`.

В CI `npm test` идёт перед каждой сборкой пакета и на каждый PR (упавший
тест не даёт выпустить релиз), а Docker-сценарии — отдельный workflow `docker-tests`,
запуск вручную: Actions → docker-tests → Run workflow. Системы — отдельные
задачи (параллельно, ~7 минут), слои образа кэшируются; таблица результатов
— во вкладке Summary прогона. Запросы лаунчера к GitHub API в тестах идут с
временным токеном прогона (`DSH_LAUNCHER_GITHUB_TOKEN` — только для
разработки; лаунчер убирает её из окружения и не печатает), чтобы не упираться
в лимит 60 запросов в час. К настоящему GitHub ходит только сценарий `proxy`,
остальные — к подставному (`DSH_LAUNCHER_GITHUB_API=http://127.0.0.1:<порт>`;
другие адреса лаунчер не принимает).

Dependabot (`.github/dependabot.yml`) раз в неделю предлагает PR с новыми
версиями Electron, ESLint и действий GitHub; такой PR проверяют юнит-тесты
и сборка пакета, Docker-сценарии запускаются вручную.

Релиз: дописать раздел `## [Unreleased]` в `CHANGELOG.md` и `CHANGELOG.en.md`,
затем `npm run release 1.16.0` — раздел становится `## [1.16.0] — <дата>`,
версия ставится в `package.json`, `package-lock.json` и `deb/control`,
появляется коммит «Версия 1.16.0» (тега ещё нет). Скрипт отказывает, если
раздел пуст, ветка не `main`, есть незакоммиченные правки или версия не выше
текущей. Дальше — только через PR (прямой пуш в `main` закрыт правилом
«Changes must be made through a pull request»): `git push origin
main:release/1.16.0`, PR, по зелёному build — мерж (свой PR сливается
без approval — `enforce_admins` выключен; чужие PR, напр. dependabot, —
с 1 approval), и тег:
`git fetch origin && git tag v1.16.0 origin/main && git push origin
v1.16.0`. По тегу CI собирает пакет и публикует релиз с описанием из обоих
CHANGELOG. Только правка файлов, без коммита: `npm run release -- 1.16.0
--no-commit`.

## Про `--no-sandbox`

Лаунчер запускает Electron с `--no-sandbox`. На части рабочих столов
(Electron 44, Ubuntu 26.04) с песочницей Chromium он падал, когда
завершается и снова запускается dsh («Перезапустить dsh», перезапуск после
сбоя). Окно показывает только локальный GUI dsh (127.0.0.1) и страницы
самого лаунчера, внешние ссылки открываются в браузере, — для такого
интерфейса это нормально.

Включить песочницу: «Настройки → Графика → Песочница Chromium» (действует со
следующего запуска; нужен SUID-хелпер — его настраивает установка пакета).
При запуске из исходников:

```sh
# из каталога проекта:
sudo chown root:root node_modules/electron/dist/chrome-sandbox
sudo chmod 4755 node_modules/electron/dist/chrome-sandbox
```

и уберите `--no-sandbox` из последней строки `run.sh`.

## Если что-то пошло не так

- Если dsh не найден (или `DSH_BIN` указывает на отсутствующий файл),
  окно предложит его установить: команда `npm install -g @deepseek-ai/dsh`
  с кнопкой «Скопировать», а если глобальный npm prefix доступен без sudo —
  кнопку «Установить» (ставит прямо из окна, с логом). Системный prefix
  (npm в `/usr`, `/usr/local`) — тоже кнопка «Установить», но установка идёт
  через pkexec: пароль спросит системный диалог. «Проверить ещё раз»
  продолжает запуск, когда dsh появился.
- Если dsh упал, лаунчер сам перезапускает его (не больше трёх раз за 10
  минут) и показывает плашку «dsh перезапущен после сбоя» с кнопкой «Журнал
  dsh…». Если dsh падает снова и снова — остаётся страница с журналом.
- Если dsh был перезапущен (например, после обновления плагина), окно
  может показывать «сессия завершена». Лаунчер следит за портом и сам
  перезагружает страницу, когда dsh снова отвечает (обычно через 2–3 с).
  Если ждать не хочется — просто `F5` в окне: куки, сессии и состояние
  интерфейса сохраняются на диске (`~/.dsh/.credentials.yaml`,
  `~/.dsh/sessions/`), поэтому разговор восстанавливается без потерь.
- Окно показывает страницу с ошибкой и последними строками журнала dsh.
- Полные журналы — «Справка → Открыть папку логов» (`dsh.log` — dsh,
  `launcher.log` — лаунчер); для сообщения о проблеме удобнее «Справка →
  Сохранить отчёт…» — один архив, токены и ключи скрыты.
- Проверьте, что в терминале команда `dsh --profile web --no-open`
  поднимается и печатает URL.
- Куки живёт в профиле Electron (`~/.config/dsh-launcher`); если хотите
  «забыть» авторизацию — закройте окно (dsh остановится) и удалите этот
  каталог.
