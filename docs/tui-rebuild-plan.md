# Визуальный редизайн TUI по образцу opencode

Базовая точка: `apps/tui-go` 0.2.0-preview.40 (ветка `feature/terminal-ui`).
Цель — не добавить функции и не ломать протокол, а **уменьшить визуальную
перегрузку интерфейса**, взяв визуальный язык TUI opencode
(anomalyco/opencode, `packages/tui` + `packages/ui` + `packages/theme`).

Протокольный слой и поведение команд не меняются; `test/real_*.py` остаются
приёмочной сетью. Меняются только внешний вид, иерархия и плотность.

## 1. Что именно берём из визуала opencode (из их исходников)

Из `packages/tui/src/ui/dialog.tsx`:
- **Приглушённый фон за диалогом** (`backgroundColor rgba(0,0,0,150)` на весь
  терминал) — диалог «выпадает» из сцены, остальной интерфейс гаснет.
  Сейчас у нас диалоги рисуются поверх плотного UI без затемнения — это
  главный источник ощущения «всё сразу видно».
- **Три фиксированных размера диалогов**: medium 60 / large 88 / xlarge 116
  ячеек, центрирование, `DIALOG_INSET = 3`, у списков ещё gutter в 1 ячейку
  под маркер ▌/●.
- **Единый шаблон диалога**: `DialogHeader` (заголовок + приглушённый `esc`
  справа, опциональная muted-подпись под заголовком), пустая строка между
  header/body/footer — `DialogLayout`. У нас шаблон диалога собран 12 раз
  по-разному.
- Клик вне диалога = закрытие (но если выделен текст — копирование, не закрытие).

Из `packages/tui/src/component/session-frame.tsx`:
- **Каркас сессии**: вертикальная рейка вкладок сессий слева, основная
  область чата, **опциональная правая панель** (терминал/панель) с ручкой
  ресайза (drag, сохраняется ширина).
- Сайдбар **складной** (`sidebarOpen` по умолчанию false) — не постоянная
  колонка, а то, что открывается.

Из `packages/theme` (`color.ts`, `resolve.ts`, `schema.ts`):
- **Семантические токены**, а не сырые цвета: `surface("dialog")`,
  `text.base`, `text.muted`, `background.base`; тема — набор токенов,
  выбор темы — отдельный диалог (`dialog-theme-list`).

Мелкие элементы, дающие «лёгкость»:
- **one-cell spinner** (одна ячейка, плавная анимация, glow-опция) вместо
  многосимвольных индикаторов;
- **fade-in / shimmer** для стримящегося текста (200 ms) — стрим читается
  как текст, а не как «догоняющая мигающая строка»;
- **тосты** (`toast.tsx`, variant error/success) вместо inline-ошибок,
  размазанных по углам экранов;
- **muted-текст для второстепенного** (подписи, контексты, метаданные) —
  в opencode почти всё, что не является содержанием, приглушено;
- **SplitBorder** — тонкие разделители, а не рамки вокруг всего.

## 2. Что в нашем текущем UI перегружает (по `apps/tui-go`)

1. Диалоги без затемнения фона и без единого шаблона — 12 диалогов, 12
   стилей; всё, что за диалогом, остаётся «живым» на экране.
2. Постоянно видимая боковая панель с деревом + статусы + подсказки —
   три колонки шума в 80×24.
3. Статусная строка и хинты клавиш — плотный сплошной текст без иерархии;
   второстепенное и основное одной яркостью.
4. Карточки инструментов — рамки вокруг каждой, даже в свёрнутом виде;
   при длинном ответе экран превращается в «стопку рамок».
5. Ошибки/статусы — inline в разных местах, без единого места для уведомлений.
6. Стили lipgloss размазаны по 30+ файлам, нет единой палитры — цвета
   не согласованы между экранами (разные акценты в разных диалогах).

## 3. Целевая структура (минимальные, только для визуала)

```
internal/theme/     # токены: text{base,muted,accent}, surface{dialog,card,status},
                    # background{base,dim}, border; темы: dark (по умолчанию), light
internal/component/ # Dialog (3 размера + backdrop), DialogLayout, DialogHeader,
                    # List (gutter + маркер ▌/●), Spinner (one-cell), Toast,
                    # Muted/Emph текст, SplitBorder
```

Остальные пакеты не трогаем в этом цикле; архитектурный рефакторинг
(god-model, god-Update) — отдельная история и в этом плане не фигурирует.

## 4. Фазы

**Фаза 0 — фиксация текущего вида.**
- Golden-захваты текущих ~15 экранов (80×24 и 100×30) в `test/golden/before/`.
  Это отсчётная точка: дальше golden обновляются **осознанно**, фаза за фазой,
  и каждый diff — это намеренное визуальное изменение.

**Фаза 1 — `internal/theme` + базовые токены.**
- Единая палитра по образцу `packages/theme`: semantic tokens + 2 темы.
- Все lipgloss-стили в коде переключаются на токены (механический, пофайловый
  перевод; поведение не меняется, golden «before» почти не сдвигается —
  допускаются только согласованные мелкие сдвиги цветов, фиксируем diff).

**Фаза 2 — единый диалог (`component.Dialog`).**
- Backdrop-затемнение, 3 размера, `DialogLayout` (header/пустая строка/body/
  footer с hint), muted `esc`, клик-вне = закрыть.
- Все 12 диалогов переводятся на шаблон (один диалог — один коммит,
  golden обновляется вместе с ним).
- Критерий: нет ни одного диалога, рисующего свою рамку/подсказки сам.

**Фаза 3 — иерархия чата и статусов.**
- Muted для метаданных (время, token-статистика, имена инструментов в
  свёрнутых карточках), base для контента, accent только для активного.
- Карточки инструментов: без рамки в свёрнутом виде (одна строка: маркер +
  имя + статус), рамка появляется только в раскрытом.
- One-cell spinner + fade-in для стрима; тосты для ошибок/успехов
  (единое место, автоисчезание).
- Статусная строка: разделение на base (состояние) и muted (подсказки клавиш);
  в 80×24 подсказки сжимаются до минимума (как в opencode: в диалоге
  подсказки — только по контексту, не весь список).

**Фаза 4 — каркас сессии (самое заметное изменение).**
- Сайдбар складной: по умолчанию — только узкая рейка вкладок сессий
  (вертикальный список, как `session-tabs-rail`), по Tab/Alt+S — полная
  панель; ширина справа — ресайз ручкой, сохраняется.
- 80×24: рейка + чат + composer; 100×30+: добавляется опциональная правая
  панель.
- Критерий: на 80×24 колонка чата не сужается сайдбаром (сейчас ~50 ячеек,
  станет больше).

**Фаза 5 — полировка.**
- Shimmer/активные состояния, анимации переходов (в рамках Bubble Tea:
  таймеры-команды), согласованные отступы (inset 3 — везде).
- Финальный проход по golden: каждый экран при 80×24, 100×30.

## 5. Порядок и критерии

- Каждая фаза: `go test -race ./...` + `test/real_*.py` зелёные;
  golden-diff ревьюится как визуальный артефакт (скриншот diff).
- Фаза 4 — самая рискованная по UX (уход от постоянного сайдбара):
  делаю её последней из «большой четвёрки», с флагом
  `--legacy-sidebar` на один релизный цикл на откат.
- Не трогаем: протокол, команды, ключи (клавиши не перемещаем — это отдельный
  вопрос, если захочется декларативные keybinds), Electron-лаунчер,
  `packages/tui-plugin-sdk`.

## 6. Оценка

- Фаза 0: 2–3 дня.
- Фаза 1: ~неделя.
- Фаза 2: ~2 недели (12 диалогов по шагам).
- Фаза 3: ~1.5 недели.
- Фаза 4: ~2 недели.
- Фаза 5: ~неделя.

Итого ~7–8 недель; после каждого этапа интерфейс можно смотреть в живую
(golden-скриншоты) и тормозить/крутить направление.
