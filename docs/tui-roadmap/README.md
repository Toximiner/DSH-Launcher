# План развития TUI

Оболочка и диалог OpenCode доступны отдельными промежуточными сборками. В `opencode.4` готовы общий каталог действий и окна выбора команд, сессий/рабочих областей и моделей. Следующий этап — инструменты, размышления и разрешения. Актуальный план: [редизайн TUI](../tui-rebuild-plan.md).

Plugin Market и Automation tasks приведены к структуре GUI: отдельные страницы, карточки и статусы; задачи фильтруются по состоянию, создаются и редактируются через форму. История доставки читается без сырого JSON, время показывается с часовым поясом. F2 в форме открывает расширенный JSON для сложных правил. Проверки ревизии и подтверждения сохраняются.

Plugins в preview.40 перенесён на отдельную страницу по образцу GUI: встроенные настройки, экспериментальные и установленные пакеты, метаданные dsh, «Ещё», маркет и добавление. Компоненты показываются отдельно только для чтения. Переключение подтверждается, сверяет исходное состояние и перечитывает результат; операции и редакторы используют существующие защиты. Настоящий dsh проверяет отмену, включение и восстановление тестового пакета без вызовов модели.

Справочник клавиш preview.40 сгруппирован по семи темам: колонки сочетаний и действий, приглушённый контекст, фильтр раздела, поиск и закреплённый заголовок при прокрутке. Проверяются полнота списка, последняя строка, RU/EN, мышь и размеры от 80×24.

Окно настроек preview.40 приближено к GUI: пять разделов слева, параметры с пояснениями справа, конфигурация и закрытие сверху. Поддержаны две области фокуса, прокрутка, мышь и возврат из вложенных панелей. Общий доступ для новых сессий открывается в редакторе dsh с проверкой ревизии; язык, тема и параметры ввода сохраняются для TUI. Проверяется наследование доступа новой сессией без изменения текущей.

Начавшийся диалог в preview.40 использует центральную колонку до 100 символов, сообщения пользователя справа, ответы слева, заголовок с пресетом и переход в историю через «Траекторию». Ввод с редактором, доступом и моделью закреплён снизу. Время и статистика берутся из dsh; кнопка копирования и Ctrl+Y сохраняют исходный текст. Проверены размеры от 80×24, мышь и настоящий dsh с тестовой моделью.

Preview.40: боковая панель приближена к GUI — основные действия сверху, рабочие области и сессии деревом, настройки и аккаунт в нижнем «Ещё». Снимки читаются из dsh без обращений к модели; дерево прокручивается отдельно. Новая сессия учитывает выбранную рабочую область.

Пустая сессия использует стартовый экран с контекстом рабочей области/пресета, текущей моделью и правами доступа. Все кнопки связаны с настоящими панелями; изменение прав требует подтверждения и повторной проверки состояния.

Preview.39: `--start` и запуск из `/runtime` повторно используют работающий локальный dsh после проверки входа по API. Если ссылка недоступна, показана подсказка вместо запуска второго процесса. Ошибка старта сохраняет диагностику и не заменяет запись владельца работающего бэкенда.

GUI/TUI теперь совместно учитывают локальных клиентов dsh: закрытие одного клиента сохраняет бэкенд для второго, последний останавливает управляемый процесс; внешний dsh остаётся внешним. Добавлены проверки обеих очередностей с настоящим dsh и отдельные GUI Docker-сценарии на CI. Отмена установки пакета выполняется по requestId через Ctrl+X; профиль/баланс аккаунта открывается в прокручиваемом просмотре.

## Preview.38: оставшиеся клиентские задачи

- В настройках TUI и GUI появился справочник клавиш с поиском и контекстом.
- Настройки TUI сохраняют тёмную/светлую тему, RU/EN и видимость боковой панели.
  Поиск сессий по имени/ID работает локально; клик выбирает строку.
  Фоновая проверка сессии больше не сдвигает список и не мигает индикатором.
- `/account`: настоящий API аккаунта DeepSeek — безопасное состояние, вход через
  браузер, отмена входа, профиль/баланс, выход с проверкой выполняющихся задач.
  Проверка живого провайдера идентификации требует интерактивного входа в браузере.
- `/files`: миниатюры PNG/JPEG/GIF, текстовый слой PDF через `pdftotext`
  (poppler-utils), текст локального HTML без скриптов. Полный файл читается через
  типизированный бинарный транспорт с лимитами. Для сканов нужен внешний OCR.
- [SDK плагинов](../../packages/tui-plugin-sdk/README.md): версионированные формы,
  действия, статусы и таблицы поверх существующих команд. Два разных примера
  проверяются общим экраном через настоящий dsh.
- `/packages`: установка, выбор совместимой версии, явное разрешение скриптов
  названных зависимостей, результат серверного отката. `/operations` сохраняет
  приватные квитанции после перезапуска клиента. Неизвестный результат требует
  проверки каталога и не вызывает автоматического повтора.
- CI дополнен сценарием dsh/pnpm с локальным npm-реестром (включая сохранение
  предыдущей версии после ошибки) и чистой установкой на Ubuntu 24.04/26.04 и Debian 13.

Внешние контракты, которых ещё нет: запись файлов с проверкой ревизии; постоянное
удаление сессии с обработкой потомков, задач и рабочей области; изменение задач
команды. Закреплённый workspaceFiles явно не предоставляет запись. Прямые правки
файлов backend не заменяют эти контракты. OAuth других провайдеров и произвольные
веб-сценарии плагинов требуют собственных поддерживаемых адаптеров.
Первую публичную доставку TUI проверяем выпуском после зелёного CI.

## Preview.37: пункты 11–13

- `/runtime` (также «Файл → Установка и dsh»): проверка Node/dsh,
  пользовательская npm-установка с живым журналом, повтор после ошибки,
  запуск/остановка/перезапуск своего процесса, путь/профиль/порт/рабочая папка.
  Установка идёт в `${XDG_DATA_HOME:-~/.local/share}/dsh-launcher-tui/versions`;
  глобальный npm и GUI не обновляются. Профиль dsh по-прежнему общий.
  Один владелец процесса/установки защищён файловой блокировкой.
- `/updates`: версии и изменения из npm/GitHub, точная версия или latest для dsh,
  атомарный выбор проверенной установки и возврат предыдущей. Запущенный dsh
  сначала нужно остановить; откат бинарника не откатывает данные профиля.
- Обновление самого TUI: готовый бинарник для своей архитектуры из релиза
  `tui-v…` с SHA-256 либо локальный файл с явно указанным SHA-256. Проверка
  `--version`, резервная копия `.previous`, атомарная замена, проверка после замены
  и автоматическое восстановление при её сбое. Для ручного возврата — пункт меню
  либо `./dsh-launcher-tui-go.previous --rollback-tui`, если новый TUI не открывается.
  Требуется право записи рядом с бинарником; новая версия применяется после
  явного перезапуска. Публикация бинарников по тегу подготовлена в CI; сам релиз
  ещё не опубликован. При отсутствии подходящего бинарника показана причина.
- `/diagnostics` (также «Справка → Диагностика»): хвост stdout/stderr своего dsh
  и операций до 256 КиБ, сохранённый журнал предыдущего запуска, отчёт tar.gz
  с правами 0600. Маскируются токены URL, Bearer/Basic, ключи, пароли и cookies,
  в том числе разбитые между записями. Профиль, окружение и история чатов не
  выгружаются. Произвольный текст журнала требует просмотра перед передачей.
  Уведомления о завершении/ошибке операции, завершении хода и запросе ответа
  пишутся в журнал; звук BEL включается отдельно. Состояния заданий остаются
  на существующих экранах снимков, фонового опроса всех jobs/schedules нет.

Проверены настоящая npm-установка закреплённого dsh в новый HOME, пустой DSH_HOME,
запуск/перезапуск/выход своего процесса и сохранение внешнего dsh. На копии
настоящего бинарника проверены обновление и восстановление из `.previous`.
Go-тесты покрывают ошибки/отмену npm, блокировку второго владельца, сохранённый
указатель версий, неудачную проверку TUI после замены и маскирование отчёта.
Экраны проверены при 100×30 и 80×24. Базовые клиентские пункты 11–13 выполнены;
публичная доставка TUI остаётся непроверенной до первого отдельного релиза.

## Preview.36: пункт 10 — клиентский блок проверен

На настоящем dsh проверены:

- shell-задание: вывод до завершения, повторное чтение, отмена/подтверждение
  остановки и переподключение без повторного запуска процесса;
- общее задание Host без владельца: чтение, обозначение потери данных и остановка
  через настоящий registry с отдельным тестовым producer;
- настоящий continuable-подагент: сообщение в очередь, переход к дочерней сессии,
  история и поиск, переподключение во время работы, остановка и возврат `/parent`;
- прямое подключение `--session <child-id>` и F8 через API родителя;
- ручной запуск расписания, отмена подтверждения, сохранённая история доставки
  и переподключение без повторной доставки.

Исправлен адрес подагента: чат и история используют ID родителя/ребёнка и режим.
Обычные ветки с унаследованным дескриптором остаются обычными сессиями.
Чат ребёнка служит для просмотра; сообщения отправляются через `/agents` родителя.
F5 обновляет снимки, автоматическая синхронизация новых панелей не заявляется.
Клиентский блок пункта 10 готов в пределах доступного API. Изменение задач команды
остаётся внешней зависимостью от backend-контракта; общий workflow-интерфейс
плагинов относится к пунктам 8–9. Перезапуск процесса dsh не обещает сохранение
исполняющихся registry jobs.

## Прогресс preview.35 по пунктам 6–10

- **6:** `/presets`: каталог, выбор до первого хода и новая сессия с пресетом.
  Согласование настоящего плана через вопросы проверено: доработка и утверждение.
  Редактор цели и защита ревизий остаются из preview.34.
- **7:** `/workspaces`, `/files`, `/compose`, `/attach`, `/terminals`: выбор папки
  новой сессии, чтение текстовых файлов страницами, многострочные сообщения,
  до четырёх файлов по 2 МиБ через receipts, настоящий TTY с возвратом Ctrl+].
  Не реализованы запись файлов и просмотр PDF/изображений/веб-документов.
- **8:** `/plugins` и `/commands`: общий каталог, формы существующих схем,
  discovery/вызов команд с подтверждением и текстовым результатом.
  Декларативный протокол/SDK пока не реализован; произвольные веб-экраны
  требуют контракта сервера или специальных адаптеров.
- **9:** `/packages` дополняет `/market`: возможности пакета, включение,
  удаление и обновление до точной версии по разрешениям dsh, результат применения,
  необходимость перезапуска и результат отката. Автоперезапуска и разрешения
  сборок зависимостей нет. Проверка реальных обновлений внешних пакетов,
  специальных OAuth/account-экранов и восстановления после перезапуска остаётся.
- **10:** `/agents`, `/tasks`, `/jobs`, `/schedules`: снимки подагентов и задач
  команды, переход к дочерней сессии, сообщение в очередь/остановка continuable,
  вывод и остановка заданий; создание/правка/пауза/удаление расписания с CAS,
  история и явный запуск. Изменение team tasks требует backend API.

Проверено на изолированном настоящем dsh: каталоги, страницы файлов, жизненный
цикл расписания, оболочка/отсоединение/закрытие, загрузка файла и точная отправка
многострочного текста, оба решения по плану. Полная регрессия чата и Go race-тесты
проходят. Снимки списков обновляются по F5; автоматической синхронизации этих
новых панелей нет. На preview.35 расширенные операции подагентов, история/запуск
расписаний, вывод заданий и обновление пакетов требовали отдельных сценариев.
Проверки фоновой работы добавлены в preview.36; обновление пакетов остаётся.
На preview.35 этапы 7–10 имели рабочую основу. Проверки пункта 10 дополнены
в preview.36 выше; пункты 7–9 остаются частичными.

## Цель и порядок работы

Терминальный Linux-клиент на Go + Bubble Tea с функциональными эквивалентами
лаунчера, dsh и плагинов. Совпадение возможностей важнее копирования веб-вёрстки.
Серверные JS-плагины продолжает исполнять dsh; Go отвечает за терминальный интерфейс.

Двигаемся небольшими шагами: одна законченная возможность, проверка, просмотр
пользователем, затем следующий шаг. Каждый этап ниже разбивается на такие шаги.
При изменении интерфейса показываем снимок настоящего приложения. Публичное
демо Pages отключено; живой просмотр возможен через приватный Codespaces.

- Вопросы агента: варианты, множественный выбор, многострочный ответ, пропуск, набор вопросов, тайм-аут и продолженный ответ.

- Текстовый чат в сессии: отправка, поток ответа, отмена, восстановление чтения без автоматической повторной отправки.
- Постраничная история сессии: F11, фиксированный снимок, переходы раньше/позже, сохранение прокрутки и черновика; Ctrl+F и F3 для поиска текста сообщений на старых страницах.
- Создание, список и подключение сессий; подтверждённые сервером режимы и команды целей.
- Запуск установленного dsh через `--start`, предложение предустановки dshmarket.
- Маркет: каталог, поиск, установленные пакеты, подтверждаемые установка,
  обновление и удаление; прогресс из API.
- Go/PTY/CI-проверки и конфигурация живого Codespaces с настоящим dsh.

Без подключения ввод остаётся локальным. Чат проверен с настоящим dsh и
контролируемым локальным провайдером; это проверка протокола, а не реальной LLM.
16 ноября нативный TUI также проверен с настроенной в GUI Qwen3.8-27B:
получен ответ настоящей модели и живой вывод команды до её завершения. Использован
отдельный временный профиль; ключи в клиент и стенд не включаются.

## Какие настройки Electron переносить

Применимы к TUI: история ввода, мышь, язык, цветовая тема, рабочая папка,
путь/профиль/порт своего dsh, обновления, журналы и уведомления, если соответствующая
функция уже реализована. Параметры запуска dsh, обновления и диагностика добавлены в preview.37
(этапы 11–13). Шрифт и масштаб обычно задаёт терминал, браузерный масштаб — оболочка
живого стенда. Нереализованные настройки не выдаём за работающие.

сворачивание в трей, полноэкранный режим Electron и проверка орфографии Chromium
в настройки TUI не переносятся.

## Плагины: четыре уровня поддержки

1. **Без отдельного экрана.** Фоновые возможности и инструменты агента исполняются
   в dsh. Их результат виден через общий чат/инструменты после этапов 2–3.
2. **Общий интерфейс из существующих данных.** Настройки строятся по схемам dsh;
   команды — по доступным серверным описаниям. Это покрывает только функции,
   которые действительно предоставляет API. Веб-действия и собственные диалоги
   не превращаются в серверные команды автоматически.
3. **Декларативный интерфейс плагина.** Базовый контракт `dsh-tui-panel/v1` реализован в SDK:
   плагин описывает формы, таблицы, действия и статусы, а TUI их отображает.
   Версия протокола и пределы возможностей проверяются клиентом.
   JS-плагин может формировать эти данные; переписывать его сервер на Go не требуется.
4. **Специальный адаптер.** Для сложных сценариев — отдельное терминальное
   представление поверх API, как текущий маркет. Общие компоненты переиспользуются.
   Если подходящего API нет, сначала требуется расширение серверной части плагина.

Стратегия — сочетать все четыре уровня. Для каждого плагина фиксируем отдельно:
работу серверной части, настройки, команды и полноценный экран. Наличие одного
экрана или установленного пакета не означает полную совместимость плагина.
HTML/React произвольного плагина Bubble Tea автоматически не исполняет.

## Проверка каждого шага

- Проверки протокола и ошибок на управляемом HTTP-стенде; PTY-проверки клавиатуры,
  мыши, изменения размера и восстановления терминала.
- Для видимых изменений — настоящие снимки широкого и узкого терминала
  (включая 100×30 и минимальные 80×24), сохранение черновика и фокуса.
- Проверка с настоящим dsh/плагином для подключаемого адаптера. Фикстуры
  и тестовая LLM не служат доказательством работы настоящего агента.
- На Linux проверяем готовый бинарный файл; установочные Docker-сценарии TUI
  добавляем по мере появления установки. Существующие GUI Docker-сценарии
  запускаются только в CI по правилам CONTRIBUTING.md.
- Небольшой коммит в `feature/terminal-ui`, проверки CI и результат для просмотра;
  слияние и релиз остаются отдельными действиями.
