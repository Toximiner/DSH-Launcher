## [Unreleased]

### Добавлено

- **Меню «Правка»** в строке меню окна: «Вырезать», «Копировать»,
  «Вставить», «Выделить всё» — те же действия, что в контекстном меню.
- **Меню «Вид»:** перезагрузить (F5), перезагрузить без кэша
  (Ctrl+Shift+R), масштаб (Ctrl+= / Ctrl+− / Ctrl+0), поиск по странице,
  проверка орфографии, полноэкранный режим (F11).
- **Поиск по странице (Ctrl+F):** панель в правом верхнем углу, счётчик
  совпадений, Enter / Shift+Enter (или F3 / Shift+F3) — следующее /
  предыдущее, Esc — закрыть.
- **Проверка орфографии** в полях ввода (русский и английский): варианты
  исправления и «Добавить в словарь» — в контекстном меню. Включается и
  выключается в «Виде». Словари Chromium скачивает при первом включении.
- **Размер окна запоминается** между запусками (и «развёрнуто»).
- **«Файл → Перезапустить dsh»** (с подтверждением; dsh, запущенный не
  лаунчером, не трогается) и **«Справка → Открыть папку логов»**.
- **В «О программе»** — путь к логам, кнопка «Папка логов» и состояние
  GPU-ускорения; если GPU отключён после сбоев — кнопка «Включить GPU
  снова» (вместо ручного удаления маркера).

### Изменено

- **Меню перестроено по привычной схеме: «Файл» (перезапуск dsh, выход),
  «Правка», «Вид», «Справка»** (проверка обновлений, папка логов, «О
  программе») вместо одного пункта «Приложение».
- **«О программе» и «Проверить обновления» — небольшое окно поверх
  лаунчера** вместо отдельной страницы. GUI dsh под ним затемняется, но
  остаётся как был — не перезагружается и не теряет введённый текст.
  Закрыть — «Закрыть», Esc или крестиком окна.
- **Проверка обновлений и скачивание пакета снова идут через системный
  прокси** (настройки GNOME/KDE или переменные `HTTPS_PROXY`), как до
  1.3.1, — но без сетевого модуля Electron, из-за которого лаунчер падал.

## [1.3.1] — 2026-10-09

### Исправлено

- **Лаунчер закрывался при открытии «О программе»** (и мог закрыться при
  «Проверить обновления»). Причина — сбой Electron: после проверки
  обновлений при старте первый же запуск внешней команды (`dpkg-query`,
  `dsh --version`) ронял процесс. Проверка обновлений и скачивание пакета
  теперь идут через сетевой клиент Node.js. Побочный эффект: системный
  прокси для них не используется — в сети, где интернет только через
  прокси, лаунчер не узнает о новой версии (как без сети), но работает.

## [1.3.0] — 2026-10-09

### Добавлено

- **Меню окна «Приложение».** Строка меню теперь всегда видна; один пункт —
  «Приложение»:
  - «О программе» — версии лаунчера (dpkg для пакетной установки,
    package.json для сборки из исходников — с пометкой) и бэкенда dsh,
    путь к dsh, Node.js и ОС; кнопка «Скопировать для отчёта» кладёт весь
    блок в буфер обмена.
  - «Проверить обновления» — по требованию сверяет последний релиз на GitHub
    и последнюю версию `@deepseek-ai/dsh` на npm, показывает результат по
    каждому компоненту (авто-установки нет — обновление по-прежнему через
    вопрос при старте).
  - «Выйти» — штатное завершение (останавливает dsh, который запустил
    лаунчер).
  Подписи меню следуют за языком окна (RU|EN) и пересобираются при
  переключении.

## [1.2.0] — 2026-10-08

### Добавлено

- **Проверка обновлений при старте.** Лаунчер спрашивает GitHub о последнем
  релизе себя и npm о последней версии `@deepseek-ai/dsh`; если есть новая
  версия и dsh запускается самим лаунчером, перед стартом dsh окно спрашивает:
  «Обновить / Не сейчас / Не спрашивать больше» (запоминается на версию —
  новый релиз спросит снова).
  - Обновление лаунчера: скачивание .deb из релиза (прогресс на странице,
    sha256 сверяется с digest ассета в GitHub) и установка через pkexec —
    polkit просит пароль системным диалогом; под root пакет копируется в
    каталог root и ещё раз сверяется по sha256, затем `apt-get install`;
    после успеха — страница «Обновление установлено» и
    авто-перезапуск лаунчера. Нет pkexec / отмена пароля / ошибка — страница
    с командой для терминала (`sudo apt install -y <deb>`) и кнопкой
    «Проверить ещё раз».
  - Обновление dsh: `npm install -g @deepseek-ai/dsh@<версия>` с живым логом,
    если глобальный prefix npm доступен без sudo; иначе — команда для
    терминала. После успеха dsh стартует сразу с новой версией (если
    запускаемый dsh остался прежним — npm ставит в другой prefix — лаунчер
    об этом говорит).
  - В режиме подключения к уже работающему dsh вопросы не показываются.
  - Запросы уходят сразу при старте, параллельно остальному; перед
    запуском dsh лаунчер ждёт их ответа не дольше ~8 с (без сети запрос
    падает сразу, и лаунчер просто не спрашивает). Отключение:
    `DSH_LAUNCHER_NO_UPDATE_CHECK=1`.
  - Для разработки/тестов: `DSH_LAUNCHER_FAKE_LAUNCHER_LATEST`,
    `DSH_LAUNCHER_FAKE_DSH_LATEST`, `DSH_LAUNCHER_FAKE_INSTALLED`.
- **Тесты.**
  - `npm test` — юнит-тесты `test/version.js` и `test/port.js`: сравнение
    версий (Debian- и semver-форматы, правила CI по тегам) и поиск pid
    процесса по слушающему порту через /proc. Запускаются в CI перед каждой
    сборкой — упавший тест не даёт собрать пакет и выпустить релиз.
  - `test/docker/run.sh` — сценарии установленного .deb в Docker на чистых
    Ubuntu 24.04 и 26.04 (Xvfb, окно через CDP): закрытие окна и сигналы,
    «усыновлённый» dsh, обновление dsh через npm и самого лаунчера через
    pkexec. В CI — отдельный workflow `docker-tests`, запуск вручную.

### Исправлено

- Закрытие окна больше не оставляет работать `dsh`, если он **сам
  перезапустился** в середине сессии (после обновления плагина): лаунчер
  «усыновлял» новый процесс и молча переходил в режим подключения, из-за чего
  при закрытии окна его никто не останавливал. Теперь такой процесс
  останавливается — его pid находится по слушающему порту.
- Закрытие окна больше не оставляет процессы `dsh`, если главный процесс
  дерева уже завершился, а в группе остались живые дочерние: проверка живости
  теперь по процесс-группе, а не по коду выхода главного процесса.
- **Повторный SIGTERM/SIGINT/SIGHUP** лаунчеру (pkill дважды, завершение
  сессии) убивал его мгновенно: Chromium обрабатывает только первый сигнал
  (штатное закрытие), а затем возвращает обработчик по умолчанию — и `dsh`,
  не успевший завершиться за это время, оставался сиротой. Теперь сигналы
  обрабатывает сам лаунчер: первый — штатное закрытие (dsh получает SIGTERM,
  через 4 с — SIGKILL), повторный или зависание дольше 8 с — сразу SIGKILL
  дереву и выход. (Прямой `kill -9` самому лаунчеру перехватить невозможно —
  в том случае `dsh` переживёт его.)

## [1.1.1] — 2026-10-03

### Исправлено

- Лаунчер не находил dsh, установленный не в `/usr/bin` (через nvm,
  `~/.npm-global` и т.п.), — в том числе поставленный кнопкой «Установить»:
  при следующем запуске снова предлагалась установка. Теперь dsh ищется в
  `PATH`, каталогах npm и всех версиях nvm, найденный путь запоминается, а
  dsh запускается с «своим» node и при запуске с ярлыка.
- На чистой Ubuntu 26.04 с Node.js из apt окно писало «npm в системе нет»:
  каталога глобальных пакетов `/usr/local/lib/node_modules` ещё нет, и это
  принималось за отсутствие npm. npm теперь ищется и в nvm (при запуске с
  ярлыка nvm нет в `PATH`).
- Установка маркета на чистой системе падала с «кодом 127»: плагинам dsh
  нужен pnpm. Теперь лаунчер ставит pnpm сам, если npm позволяет без sudo,
  а иначе объясняет, какую команду выполнить.
- После установки dsh из окна вместо интерфейса могла открыться ошибка
  «ERR_ABORTED»: две загрузки страницы прерывали друг друга.
- Слишком старый Node.js (например, 18 из apt в Ubuntu 24.04): npm ставил
  dsh без предупреждений, а потом dsh не запускался, и окно путалось
  («не найден» + хвост стектрейса). Теперь окно сразу пишет, что найден
  Node.js vX, а нужен 22+, и не предлагает ставить dsh кнопкой; для
  неработающего dsh показывается сама ошибка.

## [1.1.0] — 2026-10-03

### Добавлено

- **Плагин маркета.** Перед запуском dsh лаунчер проверяет, установлен ли
  `dshmarket` в профиле, и если нет — предлагает установить его прямо из окна
  («Установить» / «Не сейчас» / «Не спрашивать больше»).
- **Русский и английский интерфейс.** Служебные окна лаунчера (запуск,
  установка dsh, маркет, вставка токена, ошибки) — на двух языках.
  Переключатель **RU | EN** в правом верхнем углу, выбор запоминается;
  по умолчанию — язык системы, принудительно — `DSH_LAUNCHER_LANG=ru|en`.
- README на английском (`README.en.md`).
- `DSH_ARGS` разбирается как в shell: поддерживаются кавычки `"…"`, `'…'`
  и экранирование `\`.

### Исправлено

- Не работали кнопки служебных страниц: «Проверить снова», «Скопировать
  команду», «Установить» dsh и «Открыть» на странице вставки токена.
- Двойной клик «Проверить ещё раз» / «Установить» мог запустить второй
  процесс dsh, который потом не останавливался при закрытии окна.
- После повторного запуска dsh окно могло открыть URL со старым токеном.
- Окно лишний раз перезагружалось сразу после запуска dsh.
- Окно подвисало на время проверки установки dsh и npm.
- На странице «dsh не запущен» не было кнопки «Проверить снова», хотя текст
  на неё ссылался.
